# Silent failure evidence

This record separates observed tests from source inspection and checks that were not run. It refers to Soup CLI 0.77.2 and the frozen Brev run. No external API is executed.

| Stage / failure | Independent evidence | Soup coverage and limits |
| --- | --- | --- |
| Ungrounded reference despite valid JSON | The pre-training 40-row review found unstated IDs/years and ambiguous behavior. Scope filters and three manual exclusions were frozen before predictions. An injected order-ID mismatch remains a deliberate fixture. | **Data doctor missed the semantic mismatch:** exit 0/MINOR, with only a generation-marker warning. See `evidence/local-checks-additional/`. Pre-flight semantic-label detection was not separately fault-tested. Offline ship trusts supplied reference-derived scores. |
| Credential-like defaults enter prompts | A broader post-run archive scan found the same GitHub token-like default in unused schemas on source rows 17135 and 43443. Its validity is unknown; it was never used for authentication. The publication copies are redacted with original hashes retained. Original training inputs remain unchanged; a new release run needs schema sanitization. | The completed 1,000-row data-doctor output did not report this finding. Credential detection was not separately fault-tested, so no broader Soup coverage claim is made. The initial archive scan covered HF tokens only and was insufficient. |
| Train/test leakage | Unique IDs, normalized queries, all supplied tool families, and cross-split near-duplicate guards; a regression test deliberately overlaps families/queries. | The live data-doctor invocation inspected only training rows; its success does not validate these splits. Public pretraining exposure and API aliases remain unresolved. |
| Wrong template, response mask, or lost EOT | Every encoded example asserts an identical training/inference prefix, prompt labels are masked, and exactly one response EOT is supervised. Real-library tests cover repeated EOT tokens in masked prompts. | **Data doctor warned** about missing generation markers and reported EOT coverage. Its own rendering/collator differs from ours; this is not proof of our exact mask. The truncated local fixture can report no assistant turns to check, illustrating a sub-check's coverage limit. |
| Applying a misleading tokenizer repair | Transformers 4.57.6 warns about Mistral regex after saving Qwen. Actual base/merged/4-bit backend fingerprints and 1,240 prompt token sequences are identical. The suggested patch applied only in memory changes 48 sequences. See `tokenizer-regex-control.json` and `scripts/check_tokenizers.py`. | This warning comes from Transformers. The original verifier's vocabulary/template identity can miss backend drift; the added diagnostic checks full backend state. No claim of a live Soup check for this exact post-save failure is made. |
| Truncation silently removes the answer | Training selection never truncates and enforces the 1,024-token limit; generated truncations are recorded and cannot pass exact-call scoring. | **Data doctor caught** the deliberate 32-token fixture as MAJOR/exit 2. Both the local fixture and full-run control output are retained. |
| Finished run without an effective update | A real zero-LR backward/optimizer control records nonzero gradients and zero changed adapter tensors. Main training records 125 updates and reload-based enabled/disabled logit effects. Effective BA norms avoid treating random nonzero A as learning. | **Live ship rejected the untrained adapter** with `adapter_noop`. Its zero task scores are placeholders, not measured predictions. The installed source checks all-zero local LoRA B tensors; that does not prove every nonzero adapter meaningfully trained. |
| Adapter omitted during merge | Reloaded FP32 merged logits match enabled-adapter logits within the fixed tolerance. The untouched base used as a merged substitute is rejected. | Offline ship replays task/general scores; it does not itself reload or compare our merged artifact. No separate Soup merge-parity diagnostic was claimed. |
| Quantization flag without packed weights | Actual packed uint8 NF4 modules/state, serialized bytes, fresh reload and quality comparisons; the FP model mislabeled as 4-bit is rejected. | Offline ship applies supplied scores and does not inspect these packed tensors. Quantization quality is assessed separately from proof of storage format. |
| Valid JSON but wrong function or arguments | Complete typed call scoring; explicit defaults are equivalent only where documented. Raw strict exact is also retained. Tests reject prose, duplicate keys, booleans-as-numbers, wrong functions and wrong arguments. | Soup's general suites have their own scorers. They are useful regression signals, not equivalent to this task contract. Our flat schema check does not establish nested constraints, enums, ranges, authorization, or real endpoint validity. |
| General tests silently use the tool-only prompt or too few tokens | General prompts use their own user-chat template and a separately frozen 256-token budget. Raw output, stopping flags, scorer revision 7 and its fingerprint are saved. Runtime exceptions cannot silently become benchmark zeros. | Installed Soup source documents why behavioral suites require a larger generation budget. Its scorers and source revision are retained; their heuristic and small-sample limits remain. |
| Offline success mistaken for automatic execution readiness | The release policy was fixed before training and keeps artifact integrity, task improvement and deployment validation separate. Permissions, side effects and representative sandbox execution were not validated. | A Soup offline verdict is not a permission/sandbox validation. This study makes no claim to have tested production execution boundaries. |

A setup crash is different from a silent model failure. The missing compiler on the clean VM was caught by tests, repaired, and retained in `evidence/cloud-setup/`; it was not counted as a quietly wrong trained model.
